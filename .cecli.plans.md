# CLI-33: Auto Queue Prompts in TUI

## 1. Project Overview
- **Jira Ticket**: [CLI-33](https://team-16702636586024.atlassian.net/browse/CLI-33)
- **Problem Statement**: When cecli is already processing a prompt (generating a response) and user types another prompt in TUI, it gets lost — no queue mechanism exists.
- **Project Objectives**:
  1. Auto-queue user prompts when cecli is already processing
  2. Show queued prompts visually in TUI (count badge)
  3. Default max queue size = 5, configurable via args/config
  4. Add `/queue` command to view queued prompts
  5. Add `/queue-remove` command with tab completion showing selectable prompt previews

## 4. Problem Analysis and Goals
- **Problems**: Prompts typed during generation discarded; no visibility into pending work; users cannot cancel queued items; no backlog limit.
- **Goals**: Seamless auto-queuing; visual TUI indicator; queue management commands (/queue, /queue-remove N); configurable limit (default 5).
- **Why Needed**: Prevent lost work during active generation; improve UX transparency.

## 5. Architecture Overview
```mermaid
flowchart TD
    A[User types prompt in TUI] --> B{Coder processing?}
    B -->|Yes| C[Queue Prompt]
    B -->|No| D[Send immediately]
    C --> E[Update Queue Display Widget]
    E --> F{Coder idle?}
    F -->|Yes| G[Dequeue & auto-submit]
    F -->|No| H[Wait for completion]
    H --> F
    I[/queue command] --> J[Display queued prompts with indices]
    K[/queue-remove N] --> L[Remove item at index N]
```
